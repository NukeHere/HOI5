# Оценка государств и районы: первая очередь ИИ

Дата: 2026-10-31. Проект алгоритмов для обсуждения и последующей реализации. Игровой код этим документом не изменяется. Начальные численные настройки подлежат проверке.

Уточнение о стоимости реализации: [исследование игровых ИИ и практическая первая версия](ai-algorithms-and-performance.md). Полные сценарные прогнозы, детальная история разведки и обновления каждого показателя по событиям не являются обязательными условиями первого рабочего результата. Начать с периодических агрегатов, ограниченных пакетов сведений и дешёвых оценок; усложнять по результатам измерений и игровых ошибок.

## 1. Решения, уточняющие общий план

1. Нынешнее распределение армии по линии недостаточно для нового ИИ. `weighted_line_targets_for_count` выбирает позиции вдоль линии, а `plan_target_weight` добавляет ограниченную поправку по ближайшим противникам. Это не оценка состава сил, устойчивости участка и оперативной обстановки.
2. Первая реализация — наблюдения, оценки государств и районы, пока без самостоятельного управления.
3. Стратегия определяет интересы страны; макро распределяет задачи, ресурсы и силы между районами; микро выбирает конкретный гекс и способ исполнения районной задачи.
4. Одна «мощь страны» не заменяет профиль возможностей. Сводные индексы допустимы для интерфейса; решения используют исходные координаты и сценарии.

## 2. Схема данных

```text
Реальное состояние мира
    → сбор проверенных фактов и счётчиков
    → разведывательный фильтр конкретного наблюдателя
    → оценочный профиль страны и её районов
    → оценка зависимостей, влияния и военных сценариев
    → глобальные решения и районные задачи
```

```text
Estimate:
    value, lower, upper
    observed_at, received_at
    source, quality, availability

CountryAssessment(observer_id, target_id, time):
    economy: EconomyProfile
    military: MilitaryProfile
    domestic: доступные оценки устойчивости и населения
    regions: наблюдаемые профили районов
    confidence: качество отдельных групп сведений

DirectedRelationship(observer_id, A, B, horizon):
    economic_dependence[A → B]  // насколько А зависит от Б
    economic_leverage[A → B]   // насколько А способен воздействовать на Б
    military_pressure[A → B]
    political_influence[A → B]
    cultural_influence[A → B]  // отсутствует до появления исходной модели
```

Две страны могут иметь разные оценки третьей страны. Нельзя вычислить результат из точного скрытого мира и только затем добавить шум: скрытая точность уже попадёт в структуру выводов и выбор целей. Производные считаются из разрешённой оценки наблюдателя.

## 3. Псевдочестные разведданные

Это облегчённая модель сведений для ботов, не симуляция тумана войны по каждому гексу. Сервер знает реальность, но выдаёт каждому наблюдателю только разрешённый пакет.

Категории сведений:

- Свои объекты и реальные операции: точные факты. Будущие результаты и здесь остаются прогнозом.
- Публичные факты: границы, объявленная война, публичные договоры; без искусственного шума в факте события.
- Экономика другой страны: оценка отраслевых мощностей, потоков и запасов с задержкой и погрешностью.
- Вооружения другой страны: оценка состава, готовности и группировки, обычно менее точная в отношении резервов и складов.
- Прямой контакт/двусторонняя сделка: точный собственный факт контакта или объёма своей сделки; он не раскрывает все сделки и ресурсы партнёра.

Начальный профиль может давать обновление иностранной экономики раз в 7 дней с задержкой 3–7 дней; военных группировок — раз в 1–3 дня с худшей точностью скрытых резервов. Это параметры каналов, не преимущество более сложного бота. Историю для задержки хранить явно: нельзя взять текущее состояние и пометить его старой датой.

```text
ПРОЦЕДУРА ПолучитьСведения(observer, target, now):
    ДЛЯ каждого доступного канала:
        ЕСЛИ срок нового донесения не наступил:
            вернуть сохранённое донесение с увеличившейся давностью
        ИНАЧЕ:
            взять разрешённый исторический агрегат на дату наблюдения
            применить общую отраслевую и частную ошибку
            ограничить значения физически допустимыми пределами
            согласовать связанные координаты
            сохранить донесение и дату следующего обновления
```

Пример ошибки для положительных величин: `оценка = истина_на_дату × exp(смещение_канала + ошибка_показателя)`. Фиксированный диапазон смещения задаётся качеством канала. Для истинного нуля отдельный механизм «не обнаружено/возможно существует»; умножение нуля на шум никогда не обнаружит неизвестный объект. Неизвестное хранится отдельно от нуля.

Ошибка канала устойчива на протяжении периода, а повторные запросы возвращают тот же пакет. Иначе бот усреднит тысячи шумных измерений и получит точную истину. Согласованная ошибка отрасли сохраняет правдоподобность взаимосвязанных величин; очевидные факты контакта уточняют соответствующий интервал.

Давность увеличивает неопределённость. Уверенность — не измеренная вероятность правильности, пока модель не откалибрована. Политика обновлений не зависит от того, открывал ли игрок панель.

## 4. Экономический профиль

Единицы фиксируются: товары — игровые единицы, потоки — единицы за 30 игровых дней, финансы — деньги/30 дней, запасы — единицы. Фактические потоки накапливаются за окно с указанием его длины; новый мир с тремя днями истории не выдаётся за наблюдаемый месячный выпуск.

Структура:

```text
EconomyProfile:
    sectors[sector_id]
    resources[resource_id]
    finance
    logistics
    production_graph

Sector:
    installed_capacity           // при исправных объектах и заданной специализации
    operable_capacity            // с текущими повреждениями
    actual_output                // измеренный фактический выпуск
    input_availability
    utilization
    expansion_potential          // отдельный сценарий, не текущая мощность

Resource:
    domestic_output, domestic_consumption
    imports, exports             // фактические объёмы, заявки отдельно
    stock
    required_inputs              // связи с производственными рецептами
    supplier_shares
    supply_gap, stock_duration
```

Группы координат:

- Энергетическое сырьё: добыча угля, нефти, газа, торфа, урана по отдельности.
- Переработка: мощности/выпуск очищенного топлива, химии, удобрений и остальных действующих рецептов.
- Продовольствие: базовый выпуск, добавка удобрений, потребление, запас, импорт.
- Материалы и промышленность: полуфабрикаты и готовая продукция по действующим ресурсам/рецептам.
- Логистика: действующие источники снабжения, доступная торговая ёмкость, склады, уязвимость концентрации.
- Финансы: доступная оценка казны, потоки доходов/расходов, долг и обслуживание, устойчивость платежей.

«Энергетическое сырьё» не равно производству электричества. Пока нет самостоятельной электрической системы, не вводить фиктивные мегаватты и недостаток электричества, который симуляция не считает. Торф также не заменяет нефть в произвольной пропорции: замены задаются только действующими рецептами.

В `calculate_tile_production_cache` рассчитываются плановые потоки по объектам, здоровью и специализациям; реальный выпуск ограничивается запасами при исполнении производственных стадий в `MainGame.py`. Поэтому кэш не равен фактическому выпуску. Нужен журнал/счётчики выполненных производственных операций и потребления. Сбор оценки не должен вызывать изменяющий мир пересчёт/нормализацию объектов.

Формулы для ресурса r за согласованное окно:

```text
баланс[r] = выпуск[r] + импорт[r] - потребление[r] - экспорт[r]

импортная_доля[r] = импорт[r] / (выпуск[r] + импорт[r])
экспортная_доля[r] = экспорт[r] / (выпуск[r] + импорт[r])
торговая_ориентация[r] = (экспорт[r] - импорт[r]) /
                        (экспорт[r] + импорт[r])

дней_до_исчерпания[r] = запас[r] / чистый_расход_в_день[r],
                        если чистый расход положителен
```

Нулевые знаменатели обрабатываются как «нет потока/не применимо». Экспортная доля относительно текущих поступлений может превышать 1 при продаже накопленных запасов — не обрезать её и не называть долей собственного производства. Для самообеспеченности отдельно сравнивать внутренний выпуск с внутренней потребностью; экспорт по обязательствам рассматривать в сценарии. Одно соотношение экспорта/импорта не показывает масштаб и критичность потоков.

Хранить также различие между фактическим и требуемым потреблением. При дефиците фактическое потребление падает; это не означает, что страна больше не нуждается в товаре.

Производственный граф строится из `PRODUCTION_RECIPES` и иных реально исполняемых правил расхода. Проверка сценария «исчез импорт газа» пересчитывает доступные входы, фактические ограничения стадий и последствия для выходов на заданном горизонте. Не суммировать стоимость сырья, полуфабрикатов и готового товара как независимый ВВП: это повторный счёт одной цепочки.

Результаты должны объяснять слабость: «перерабатывающие мощности высоки, но сырьё импортируется и собственного запаса хватит ненадолго», а не только «экономическая мощь 73».

Для сравнений хранить исходные значения и нормированные признаки. Начальная нормировка положительной координаты: `log(1 + x / reference_r)`, где `reference_r` задан в настройках с единицами. Относительная доля в мировом выпуске — отдельная координата. Изменение мирового лидера не должно менять абсолютную оценку собственной способности производить топливо.

## 5. Военный профиль и конкретная обстановка

Разделяем: состав вооружённых сил; готовность; способность поддерживать действия; возможности в конкретном районе против конкретного противника.

```text
MilitaryProfile:
    personnel: действующие люди, доступная оценка резерва
    equipment: количество по реально учитываемым типам, качество/характеристики
    capabilities:
        противопехотный огонь
        противотанковые возможности и пробитие
        защищённость
        оборона и прорыв
        мобильность
        авиация по ролям
        ПВО и перехват
    readiness: распределения организации, прочности, укомплектованности
    sustainment: запасы, расход, пополнение и доступное снабжение
    deployments: силы по районам и время их подхода
```

Если в текущей модели нет достоверного учёта единиц конкретного вооружения, использовать характеристики шаблона/соединения с пометкой «эквивалент возможностей». Нельзя из soft_attack восстановить точное число орудий. Не умножать полную атаку дивизии на численность, если атака уже относится ко всей дивизии: численность учитывать через предусмотренные боевыми правилами коэффициенты укомплектованности.

Сохранять распределение готовности: средняя организация скрывает различие между половиной разгромленных и половиной свежих частей. Национальный запас и доступность снабжения на фронте — разные координаты.

```text
ПРОЦЕДУРА ОценитьВоенныйСценарий(A, B, район, горизонт):
    получить оценённые силы, способные прибыть за горизонт
    учесть их занятость, время подхода и другие обязательные направления
    выбрать допустимые направления боя и местные условия
    рассчитать полезный состав с учётом ширины и характера противника
    применить те же зависимости готовности/брони/пробития/снабжения,
        которые использует боевая модель, без повторного умножения штрафов
    ограничить длительность действий доступными запасами и пополнением
    проверить отход, риск обхода и поддержки
    повторить для благоприятного, основного и неблагоприятного сценариев
    вернуть интервалы результата, цену и главные ограничения
```

Результат: оценка возможности удержания/прорыва, достижимый темп, время до истощения, потребность в резерве и причины риска. На первом этапе категории «вероятно удержим / исход неустойчив / вероятно не удержим» лучше неоткалиброванных процентов победы.

Силы суммируются только там и тогда, где могут действовать совместно. Нельзя считать все дивизии страны одновременно на каждом фронте. Военная угроза направленная: способность А защищаться от Б не равна способности А наступать на Б.

## 6. Зависимости и влияние

Влияние всегда рассматриваем по направлению А → Б и механизму воздействия. Слабость Б не создаёт автоматически рычаг именно у А.

### Экономический рычаг

```text
ПРОЦЕДУРА ОценитьЭкономическийРычаг(A, B, H):
    baseline = прогноз экономики Б на H при текущих условиях
    disruption = тот же прогноз без поставок/финансирования со стороны А
    в disruption разрешить реально доступные замены и альтернативные поставки
    ущерб_Б = потеря значимых результатов между двумя сценариями
    цена_А = потеря выручки, встречных поставок и иных выгод для А
    вернуть ущерб_Б, цена_А, время появления эффекта, неопределённость
```

Для альтернативных поставщиков учитывать свободное предложение, торговую ёмкость, дипломатический доступ и конкурирующий спрос. Одна свободная партия не может спасать все страны одновременно. Неизвестный контрагент внешнего рынка хранится как внешний источник; его нельзя приписать А.

Сначала достаточно координат рычага по топливу, продовольствию, промышленным входам, кредиту. Если нужен сводный балл: нормированная потеря целевых результатов Б по сценариям с явными весами. Более полезно показывать механизм: «эмбарго А ограничит выпуск топлива Б через 20–40 дней; А тоже теряет значимую выручку».

### Политическое влияние

Возможность А добиваться от Б выгодных решений зависит от конкретного действия: экономического рычага, достижимого военного давления, доверия, репутации, совместимости интересов, обязательств и доступных альтернатив Б.

Сначала сохранять вектор этих факторов и оценивать полезность предложения для Б с/без отказа. Будущую вероятность принятия можно калибровать на результатах дипломатической модели. Не применять новую формулу влияния поверх старого порога ответа, дважды учитывая одни и те же отношения.

### Культурное влияние

Из денег и танков культурное влияние достоверно не получается. Нужны собственные исходные переменные: культурное производство и распространение, образование, доступ к аудитории, связи обществ, восприимчивость и история контактов. Экономика может финансировать эти каналы, но не заменяет их.

В текущей модели такой системы нет. Первая версия хранит `cultural_influence = unavailable`, а идеологическую близость — отдельным существующим признаком. Будущая формула должна описывать передачу воздействия через реальные каналы и инерцию восприятия, а не сразу менять идеологию при росте бюджета.

## 7. Определение района

Район — связная, достаточно компактная группа гексов с устойчивым ID, используемая как единица назначения макрозадач. Производственная специализация и оборонная роль — свойства района; они не обязаны быть единственными и не должны постоянно менять его границы.

Нужны два связанных представления:

1. **Базовый географический район.** Устойчивый набор гексов, общий для системы мира. Границы не зависят от закрытых сведений о противнике.
2. **Управляемая часть района.** Связные компоненты пересечения района с текущей территорией страны. При захвате часть района переходит другому владельцу, а географический ID сохраняется. Учитывать `base_region_id`, `owner_id`, `component_id` и историю разделения/слияния.

Иначе потеря одного гекса будет переименовывать всю карту задач. Несвязанные куски одного района нельзя считать единой доступной площадкой. Морские и воздушные связи при их наличии — отдельные рёбра доступности, не сухопутная связность.

Фронт может пересекать несколько районов. Это оперативный слой поверх устойчивых районов, а не причина перерезать экономическую карту ежедневно.

## 8. Алгоритм построения районов

Начальная версия строится по открытой географии, доступным центрам и транспортной доступности. Экономическая однородность не является обязательным условием: район может содержать и добычу, и переработку. Не подгонять границы к каждому месторождению.

```text
ПРОЦЕДУРА ПостроитьБазовыеРайоны(карта):
    построить граф сухопутной проходимости гексов
    выделить связные компоненты

    ДЛЯ каждой компоненты:
        выбрать начальные центры: открытые крупные поселения, затем
            наиболее удалённые по времени пути непокрытые места
        ограничить плотность центров минимальным расстоянием
        выполнить многоточечный поиск кратчайших путей от центров
            с фиксированными неотрицательными ценами перехода
        каждому гексу назначить центр с минимальной стоимостью пути
            при равенстве использовать устойчивый ID

        пока район превышает допустимый диаметр или сильно слишком велик:
            добавить центр в удалённой части
            повторить назначение

        слишком малые районы объединять с доступным соседом,
            только если сохраняются связность и ограничение диаметра

    сохранить ID, гексы, соседей, центры и версию разбиения
```

Цена перехода использует текущую географическую проходимость; добавочные штрафы горных границ/водных переходов допустимы только при наличии соответствующих данных. Движение армии и доставка товаров могут иметь разные графы: районный путь — оценка географической доступности, не замена реальному поиску пути дивизии.

Число районов подбирается масштабом карты и допустимым внутренним временем перемещения. Примерная целевая площадь — параметр; равное число гексов не является требованием. Для маленькой страны естественен один район, для островов — отдельные компоненты.

Многоточечный поиск с общей фиксированной стоимостью рёбер даёт связные области по деревьям предшественников. После любого слияния/ручной правки связность проверяется явно. Не использовать обычный k-means по координатам: он может объединить места, разделённые непроходимой географией.

Базовые районы создаются при генерации мира, а не пересчитываются после каждого боя. Редкий большой пересмотр требует таблицы соответствия старых и новых ID по перекрытию и переноса активных задач. Изменения владельца обновляют управляемые компоненты и их агрегаты.

## 9. Профиль района

```text
RegionProfile:
    identity: base_id, owner_id, component_id, tile_keys, neighbours
    geography: центр, площадь, доступность, соседние границы, время подхода
    population: численность, плотность, доступная ёмкость поселений
    economy: тот же отраслевой и ресурсный профиль, что у страны
    specialization: веса отраслей + абсолютные масштабы
    infrastructure: склады, снабжение, действующие транспортные объекты
    military: присутствующие силы и доступный по времени резерв
    defense: местность, укрепления, ПВО, уязвимые подходы
    importance: население, выпуск, критические цепочки, географические связи
    vulnerability: угрозы по направлениям и сценариям
    placement_options: доступные классы улучшений и оценка вместимости
```

Население брать из действующей модели гексов. Если источник оценочный, районная сумма тоже обозначается оценкой. В текущей экономике ограничение производства может применяться на уровне страны/стадии; региональный фактический выпуск нельзя восстановить точно из одних плановых кэшей. Первое приближение — распределить фактический выпуск стадии пропорционально плановым выходам района и пометить как атрибуцию, а не наблюдаемую транспортировку товара. Позже счётчики операций дадут более точное распределение.

Специализация — несколько весов. Для сравнения разных товаров использовать фиксированные базовые цены или другую явную общую меру вклада, а не складывать тонны нефти с количеством готовых изделий. В межотраслевом сравнении избегать повторного счёта цепочки. Хранить отдельно специализацию установленной мощности и текущего выпуска: дефицит сырья не уничтожает промышленное назначение района.

Важность не равна текущей выручке:

```text
критичность_района(H) = последствия сценария его недоступности на горизонте H
```

Потеря единственного ключевого входа может иметь больший эффект, чем потеря богатого, но заменимого предприятия. В первой версии район «недоступен» означает исключение его вкладов/действующих логистических функций в модели; не вводить последствия перекрытия путей, которых сама модель снабжения не учитывает. Риск физического отрезания войск можно оценивать отдельно по реальным маршрутам движения.

Вектор важности зависит от задачи: для обороны — риск утраты населения/производства и прохода; для развития — прирост выпуска на вложение; для наступления — военная доступность и эффект на противника. Один неизменный балл важности не определяет все решения.

## 10. Макро распределяет, микро размещает

```text
Макро:
    район R должен получить дополнительное прикрытие ПВО
    защищаемые функции: переработка топлива и пункт снабжения
    бюджет: B
    доступные средства: набор S
    срок: D
    ограничение: не создавать дефицит боеприпасов

Микро:
    перечислить допустимые гексы района R
    оценить дополнительное прикрытие защищаемых объектов
    проверить дальность, размещение, стоимость, снабжение и риск
    выбрать допустимый вариант в рамках B и S
    отправить команду и дождаться результата

Если подходящих мест нет:
    вернуть макро причину, лучший доступный эффект и соседние альтернативы
```

Макро должно иметь агрегированную оценку реализуемости, чтобы не раздавать бессмысленные задачи. Микро может выполнить пробный поиск размещения без изменения мира и вернуть стоимость/эффект. Изменение района, бюджета или состава средств подтверждается макро; сам выбор гекса остаётся у микро. Для взаимосвязанных объектов микро рассматривает маленькие комплекты вариантов, а не всегда выбирает каждый объект жадно независимо.

Силы распределять по ожидаемому снижению риска или приросту результата. Учитывать минимальный полезный комплект, время подхода и центральный резерв. Десять одинаковых частей не обязаны делиться поровну между двумя районами: решают доступный противник, ценность потери и возможность действительно изменить исход.

## 11. Ближайшая последовательность реализации

1. Утвердить перечень координат, единицы и контракт `Estimate`; отдельно отметить отсутствующие механики.
2. Добавить чистые точные агрегаты и накопление фактических потоков производства/потребления/сделок. Они доступны сборщику фактов, но не напрямую чужому планировщику.
3. Построить устойчивые районы и агрегирование собственных показателей. Проверить покрытие территории, связность, отсутствие двойного счёта и устойчивость ID.
4. Реализовать разведывательные пакеты по наблюдателям, историю, задержки и устойчивые ошибки.
5. Собирать экономические/военные профили из этих пакетов. Сначала выводить объяснения и диапазоны без принятия управляющих решений.
6. Добавить сценарии прекращения поставок, недоступности района и локального военного столкновения. Выводить механизмы зависимости и давления.
7. Подключить результаты к первому макрораспределению между районами и новому выбору гексов микроуровнем.

Готовность первого этапа: по каждой паре наблюдатель/цель можно объяснить, что известно, насколько это свежее, где сильные стороны, какие входы критичны, какие районы важны и какие выводы остаются неопределёнными. Никаких обещаний качественного управления армией до проверки отдельного исполнителя.

Проверки поведения оценок: повторные запросы не раскрывают истину; задержка использует прошлый снимок; своё известно точно; пустое значение не равно нулю; частичная поставка не считается полной; повреждение уменьшает действующую мощность; запас временно поддерживает выпуск после прекращения импорта; сильная армия далеко не считается немедленной угрозой; отсутствующая культура остаётся неопределённой; изменение владельца не теряет гексы и не дублирует население/производство.
