# Районы CAS и передовые базы

22 ноября 2026: исправлены исходники; после разрешения пользователя выполнена Release-сборка.

Причина: фронт считался доступным по любой собственной клетке региона с текущей базы. Передовая база не участвовала в выборе района, а перебазирование рассматривалось только после выбора. При неудаче оставался район задания, часто столичный. Дополнительно инфраструктурные цели стояли раньше наземной поддержки в оценке базы.

Теперь специализированные CAS-крылья (штурмовики, вертолёты, истребители-бомбардировщики без роли перехвата) выбирают реальный вражеский край фронта с учётом текущей базы и доступных мест на передовых базах. Доступность мест считается один раз для каждого крыла/базы, вне цикла клеток фронта. Баланс крыльев по регионам считается отдельно по ролям. Для CAS при выборе базы первой идёт достижимость фронта, район ограничивается фронтовыми клетками/целями поддержки, фильтр «Войска» включён даже до появления конкретной вражеской дивизии. Тыловые промышленные цели не вытесняют наземную поддержку из стратегического списка CAS.

Если подходящей базы ещё нет, целью развёртывания остаётся фронт. Если активного собственного фронта нет, CAS не получает фиктивную оборону столицы: старый район и ударные задания снимаются. Создание передовой инфраструктуры остаётся в существующем планировщике. Истребители сохраняют возможность воздушной обороны тыла.

Добавлен `--check-bot-cas-front` / CTest `bot_cas_front_deployment`: штурмовики и вертолёты с недостижимой из столицы границей должны перебазироваться на существующую передовую базу, включить «Войска» и получить фронтовой район. Вторая часть проверяет назначение наземных дивизий на вражескую границу. Общий алгоритм наземного распределения в этой правке не изменён: по скриншоту нельзя установить причину отсутствия конкретных наземных дивизий.

`git diff --check` и все 61/61 CTest прошли, включая `bot_cas_front_deployment`, `bot_air_planning_python_parity`, `bot_allied_border_distribution`, `air_strike` и сохранение/загрузку.
